# WriteLoop 질문 답변 피드백 프롬프트 개선 전후 테스트 보고서

> 이 문서는 초기 프롬프트 개편 단계의 기록이다. Luna 최적화와 최종 50대 50 모델 비교는 `writeloop-feedback-luna-optimized-prompt-ab-report-2026-07-12.ko.md`를 기준으로 한다.

작성일: 2026-07-12  
대상: 질문 답변형 영어 피드백 생성 로직  
대상 모델: OpenAI `gpt-5.4-mini`  
추론 강도: `low`

## 1. 보고서 요약

이번 작업은 WriteLoop 질문 답변 피드백의 미션 선택 정확도와 응답 일관성을 높이기 위해 프롬프트, OpenAI 응답 스키마, 자동 품질 평가기를 함께 개편한 결과를 정리한다.

동일한 50개 사례를 최신 평가 규칙으로 다시 비교한 결과는 다음과 같다.

- 엄격 통과율: 38%에서 70%로 상승
- 콘텐츠 미션 스캐폴드 제공률: 0%에서 100%로 상승
- 미션과 첫 교정 포인트 불일치: 32건에서 3건으로 감소
- 평균 품질 점수: 6.20점에서 6.52점으로 상승
- 평균 응답 시간: 9.64초에서 8.31초로 단축
- 완료 판정 정확도: 90%에서 82%로 하락
- 허용 가능한 미션 선택: 42건에서 35건으로 하락

따라서 이번 개편은 **응답 구조, 학습 스캐폴드, 중복 제거, 지연 시간**을 뚜렷하게 개선했다. 반면 **이유 미션 과선택, 조기 완료, 영문과 한국어 의미 불일치, 잘못된 문법 설명**은 다음 개선 단계에서 해결해야 할 핵심 문제로 남았다.

## 2. 테스트 설계

### 2.1 평가 사례

평가셋은 운영 중인 활성 질문에 연결된 50개 답변으로 구성했다.

| 유형 | 건수 |
|---|---:|
| 일반적인 이유 | 5 |
| 내용 부족 | 5 |
| 문법과 내용이 함께 부족 | 4 |
| 의미를 막는 문법 오류 | 3 |
| 가벼운 문법 오류 | 5 |
| 지나치게 짧은 답변 | 3 |
| 질문과 무관한 답변 | 5 |
| 필수 내용 누락 | 4 |
| 충분히 좋은 답변 | 6 |
| 일반적인 계획 | 3 |
| 그 밖의 슬롯·마무리·자연스러움 유형 | 7 |
| 합계 | 50 |

평가 파일은 `scripts/feedback-quality/cases.prompt-refactor-50.json`이다.

### 2.2 실행 조건

- 개선 전후 모두 `gpt-5.4-mini` 사용
- reasoning effort `low` 사용
- 동시성 1로 순차 실행
- 동일한 질문과 답변 사용
- 활성 질문 사전 검증 후 호출
- 성공 응답도 전체 payload를 저장
- 모델 변경 효과가 섞이지 않도록 `gpt-5.6-terra`는 이번 비교에서 제외

### 2.3 비교 시 주의사항

개선 전 원시 리포트에는 모든 사례가 `missing_success_check`로 실패한 것으로 기록돼 있다. 당시 평가기가 이미 응답 스키마에서 제거된 `successCheckKo`를 계속 필수로 요구했기 때문이다.

따라서 원시 수치인 `0/50`은 실제 피드백 품질을 의미하지 않는다. 본 보고서는 저장된 개선 전후 응답을 **동일한 최신 평가 규칙으로 다시 판정한 결과**인 `19/50`과 `35/50`을 사용한다.

또한 LLM 응답에는 비결정성이 있으므로, 이번 결과는 한 번의 고정 평가셋 회귀 실행 결과다. 모델 자체의 통계적 우열을 확정하려면 같은 평가를 여러 차례 반복해야 한다.

## 3. 주요 개선 내용

### 3.1 시스템 지침과 학습자 데이터 분리

기존에는 학습자 답변이 개발자 프롬프트 문자열 안에 직접 들어갔다. 이를 다음과 같이 분리했다.

- 고정 정책과 미션 철학은 developer message로 전달
- 질문, 현재 답변, 이전 답변, 힌트와 메타데이터는 JSON user message로 전달
- 학습자 답변 안의 명령문, 역할 표기, 마크업은 지시가 아닌 데이터로 취급

이 변경은 프롬프트 인젝션 위험을 줄이고, 고정 지침과 사용자 입력의 경계를 명확하게 만든다.

### 3.2 프롬프트 간소화

중복되거나 서로 충돌하던 지침을 제거하고 다음 핵심 순서로 재구성했다.

1. 답변의 의미와 질문 수행 여부 진단
2. 학습자가 이미 말한 슬롯과 빠진 슬롯 구분
3. 지금 가장 가치 있는 행동 하나 선택
4. 모든 피드백 섹션을 같은 행동에 정렬
5. 충분한 답변은 `COMPLETE`로 종료

### 3.3 미션 선택 우선순위 명시

미션 우선순위를 다음과 같이 고정했다.

1. 유효한 영어 답변이 없으면 `TASK_RESET`
2. 의미 이해나 유용한 재작성을 막는 오류가 있으면 `GRAMMAR_FIX`
3. 질문이 요구한 필수 슬롯이 빠졌으면 해당 내용 미션
4. 필수 내용이 충족됐지만 핵심 문법 오류가 있으면 `GRAMMAR_FIX`
5. 답변이 지나치게 일반적일 때만 선택적 내용 확장
6. 충분히 발달한 문장의 핵심 표현만 어색하면 `EXPRESSION_POLISH`
7. 고칠 가치가 큰 문제가 없으면 `COMPLETE`

`ADD_DETAIL`, `ADD_REASON`과 같은 비표준 미션 코드는 제거하고 정규 미션 코드만 스키마에서 허용했다.

### 3.4 슬롯 기반 진단 강화

`presentSlots`, `missingSlots`, `chosenSlot`을 사용해 다음 규칙을 적용했다.

- 질문에 이미 포함된 시간과 장소를 학습자가 직접 말한 슬롯으로 계산하지 않음
- 학습자가 이미 말한 이유를 다시 이유 미션으로 선택하지 않음
- `to + 동사` 목적 표현도 문맥상 이유라면 `REASON`으로 인정
- `because it is good`처럼 일반적인 이유도 이유가 존재한다고 판정하고, 같은 이유를 반복 요청하지 않음
- 내용 미션의 `chosenSlot`은 반드시 `missingSlots`에 포함돼야 함

### 3.5 OpenAI 응답 스키마 정리

중복되거나 사용되지 않던 다음 필드를 OpenAI 생성 스키마에서 제거했다.

- `contentOpportunity`
- `selectedMissionReason`
- `contentNeed`
- `whyChosenKo`
- `whyNotGrammarFirstKo`
- `addOnExampleEn`
- `addOnPlacementKo`
- `minorFixes`
- `placeholderEn`
- `successCheckKo`

미션 선택의 기준은 `missionDecision`에, 사용자에게 보여 줄 행동은 `coachMission`에 집중하도록 정리했다.

### 3.6 품질 평가 자동화 보강

자동 평가에 다음 검사를 추가하거나 수정했다.

- 완료 응답은 숨겨진 coach move를 요구하지 않음
- 내용 미션은 영문·한국어 스켈레톤과 추천 표현을 요구
- 교정 미션의 before 문구가 실제 학습자 답변에 존재하는지 확인
- 완료 예상 사례의 미완료와 계속 예상 사례의 조기 완료를 모두 검출
- 첫 교정 포인트와 미션의 불일치를 경고
- 응답 평균, P50, P95 지연 시간 기록
- 개선 전후 사례별 점수와 회귀 사례 비교

`GRAMMAR`와 `GRAMMAR_FIX`, `TOPIC`과 `TASK_RESET`을 서로 다른 값으로 오판하던 평가기 정규화 문제도 수정했다.

## 4. 개선 전후 50건 비교

아래 표는 `comparison.json`이 개선 전후 payload를 동일 규칙으로 재평가한 결과다.

| 지표 | 개선 전 | 개선 후 | 변화 |
|---|---:|---:|---:|
| 요청 성공 | 50/50 | 50/50 | 동일 |
| 엄격 통과 | 19/50, 38% | 35/50, 70% | +16건, +32%p |
| 허용 가능한 미션 선택 | 42/50 | 35/50 | -7건 |
| 핵심 코치 필드 완성 | 50/50 | 50/50 | 동일 |
| 미션 지원 정보 완성 | 23/50 | 50/50 | +27건 |
| 콘텐츠 스캐폴드 제공률 | 0% | 100% | +100%p |
| 근거 있는 before/after | 100% | 100% | 동일 |
| 완료 판정 정확도 | 90% | 82% | -8%p |
| 평균 품질 점수 | 6.20/7 | 6.52/7 | +0.32 |
| 평균 추천 표현 수 | 2.54개 | 1.72개 | -0.82개 |
| 첫 교정 포인트 불일치 경고 | 32건 | 3건 | -29건 |
| 평균 응답 시간 | 9.641초 | 8.311초 | -1.330초 |
| P50 응답 시간 | 9.676초 | 8.045초 | -1.631초 |
| P95 응답 시간 | 13.968초 | 11.690초 | -2.278초 |

### 4.1 사례별 변화

- 개선: 25건
- 변화 없음: 16건
- 회귀: 9건

가장 큰 개선 사례는 구체적인 계획이 이미 있는 답변이다. 개선 전에는 불필요한 `REASON`을 요구했지만, 개선 후에는 `COMPLETE`로 종료해 점수가 4점에서 7점으로 올랐다.

짧은 답변, 질문과 무관한 답변, 일반적인 이유를 가진 답변에서는 다시 쓸 수 있는 스켈레톤과 추천 표현이 항상 제공되기 시작했다. 이는 엄격 통과율 상승의 가장 큰 원인이다.

### 4.2 수치 해석

엄격 통과율은 크게 개선됐지만, 허용 가능한 미션 선택과 완료 정확도는 낮아졌다. 이는 개선 후 응답이 형식적으로는 더 완전해졌지만 다음 두 경계에서 오판이 늘었음을 의미한다.

- 충분하지 않은 답변을 너무 일찍 `COMPLETE` 처리
- 문법이나 세부정보보다 `REASON`을 과도하게 선택

따라서 70%라는 엄격 통과율만으로 피드백 의미 품질이 완성됐다고 판단하면 안 된다.

## 5. 최종 보정 후 마지막 14건 테스트

50건 개선 후 남은 우선순위 규칙을 보정하고 37번부터 50번까지 14건을 다시 실제 호출했다.

### 5.1 자동 평가

| 지표 | 결과 |
|---|---:|
| 전체 | 14건 |
| 자동 통과 | 10건, 71.4% |
| 자동 실패 | 4건, 28.6% |
| 평균 응답 시간 | 9.327초 |
| P50 | 8.748초 |
| P95 | 14.759초 |

자동 실패 4건은 다음과 같다.

| 사례 | 자동 판정 | 최종 해석 |
|---|---|---|
| 자유 시간 활동을 세 문장으로 답함 | 불필요한 `REASON` 선택 | 실제 프롬프트 결함 |
| 주말 습관을 과거형으로 답함 | `REASON` 선택 | 질문 메타데이터와 평가 라벨 충돌이 큰 원인 |
| 말하기 자신감 목표와 모호한 계획 | 너무 이른 `COMPLETE` | 실제 프롬프트 결함 |
| `makes my stress disappear` 사용 | `GRAMMAR_FIX` 선택 | 올바른 문법을 오류로 설명한 실제 결함 |

### 5.2 서브에이전트 의미 품질 교차검토

자동 규칙은 필드 존재 여부와 미션 코드 정합성에는 강하지만, 영문과 한국어의 의미 일치나 문법 설명의 사실성까지 완전히 판단하지 못한다. 이에 14건 전체를 서브에이전트가 독립 검토했다.

- 독립 합격: 5/14
- 독립 실패: 9/14
- 완전 합격: 3건
- 경고부 합격: 2건

자동 통과 사례에서 추가로 발견된 문제는 다음과 같다.

1. 완료 판정과 낮은 점수가 서로 모순됨
2. 한 가지가 아니라 두 가지 행동을 동시에 요구함
3. 추천 표현의 한국어 의미에 원문에 없는 내용을 추가함
4. `skeletonKo`에 한국어 대신 영어를 출력함
5. 영문 모델답안과 한국어 해석의 의미가 다름
6. 부자연스러운 영어 표현을 학습 표현으로 추천함
7. 영문에는 없는 이유와 행동을 한국어 번역에서 창작함
8. “좋아하는 계절이 없다”는 유효한 입장을 무시하고 특정 계절을 선택하도록 강제함
9. 문법적으로 올바른 `make + 목적어 + 동사원형`을 잘못된 문법으로 설명함

이 결과는 자동 통과율과 실제 교육 품질을 별도로 관리해야 한다는 점을 보여 준다.

### 5.3 평가기 경고 보정

마지막 14건 원시 리포트에는 첫 교정 포인트 불일치 경고가 5건 기록돼 있다. 확인 결과 다음처럼 의미가 같은 내부 코드의 표기 차이였다.

- `GRAMMAR`와 `GRAMMAR_FIX`
- `TOPIC`과 `TASK_RESET`

평가기 정규화 수정 후 동일 payload를 재평가한 결과는 다음과 같다.

- 자동 통과 10건
- 자동 실패 4건
- 잘못된 불일치 경고 0건

## 7. 최종 결론

이번 개선은 단순 문구 수정이 아니라 피드백 생성 계약을 재구성한 작업이다.

개선 효과가 확실한 부분은 다음과 같다.

- 프롬프트 지침과 학습자 데이터의 안전한 분리
- 중복 스키마 제거
- 모든 콘텐츠 미션에 즉시 사용할 수 있는 스캐폴드 제공
- 미션과 첫 교정 포인트의 구조적 정렬
- 충분한 답변의 불필요한 반복 학습 감소
- 평균 및 상위 지연 시간 감소

그러나 실제 사용자 품질 관점에서는 아직 다음 문제가 남아 있다.

- 이유 미션 과선택
- 구체성이 부족한 답변의 조기 완료
- 문법 설명의 사실 오류
- 영문과 한국어 필드의 의미 불일치
- 학습자의 원래 입장 변경
- 한 번에 한 가지라는 미션 철학 위반

따라서 현재 상태는 **구조적 안정성은 크게 개선됐지만 의미 품질 자동화는 한 단계 더 필요한 상태**로 평가한다.

## 8. 다음 개선 우선순위

1. `suggestionEn`, `suggestionKo`, `modelAnswer`, `modelAnswerKo`의 의미 일치 규칙을 추가한다.
2. 문법 교정은 원문에서 실제 오류를 다시 확인하고, before와 after가 실질적으로 달라야만 허용한다.
3. “선호 없음”, 부정문, 모름과 같은 학습자의 입장을 보존한다.
4. 이유 요구 여부는 메타데이터만이 아니라 실제 질문 문장과 함께 판정한다.
5. 한 미션에서 요구하는 새 행동을 한 가지로 제한한다.
6. `skeletonKo`의 한국어 포함 여부와 표현 번역의 기본 정합성을 자동 검사한다.
7. 결정적 규칙 검증과 별도로 의미 품질 judge를 도입해 번역·사실성·입장 보존을 평가한다.
8. 프롬프트 품질이 안정된 뒤 같은 50건으로 `gpt-5.4-mini`와 `gpt-5.6-terra`를 별도 비교한다.
