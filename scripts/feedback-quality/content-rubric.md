# 문장 피드백 내용 채점 루브릭

학생에게 보인 피드백의 내용이 좋은지 채점한다. 미션 종류가 맞는지는 회귀 케이스(`cases.*.json`의 기대 미션)가 보고, 이 루브릭은 학생이 읽는 내용의 질을 본다.

## 쓰는 법

1. 평가셋을 실제 OpenAI로 돌린다(요청 수는 돌리기 전에 승인받는다). 리포트에 통과한 케이스의 피드백도 남아야 하므로 `--include-pass-payloads`로 돌린다(`scripts/dev/run-llm-smoke.sh`는 늘 이렇게 돈다).

   ```
   bash scripts/dev/run-llm-smoke.sh --out <결과 폴더> --cases scripts/feedback-quality/cases.content-quality-40.json --expect-requests <승인받은 수>
   ```

2. 채점 묶음을 만든다.

   ```
   node scripts/feedback-quality/export-content-review.mjs \
     --report <결과 폴더>/reports/cases.content-quality-40/latest.json \
     --cases scripts/feedback-quality/cases.content-quality-40.json \
     --out <채점 폴더>
   ```

3. 메인 세션이 채점 에이전트를 부른다. 채점 에이전트는 이 루브릭과 `review-items.json`만 받는 새 에이전트다. 구현, 명세, 앞 실행의 점수는 읽지 않는다. 항목을 10건 안팎의 묶음으로 나눠 에이전트 여러 개가 동시에 채점하게 하고, 결과를 하나의 `scores.json`으로 합친다.
4. 점수를 모은다.

   ```
   node scripts/feedback-quality/summarize-content-scores.mjs --scores <채점 폴더>/scores.json --items <채점 폴더>/review-items.json [--compare <앞 실행의 scores.json>]
   ```

## 채점 출력 형식

`scores.json`은 항목마다 하나씩 쓴 배열이다.

```json
[
  {
    "id": "review-items.json의 id 그대로",
    "scores": {
      "correctionAccuracy": 4,
      "correctionExplanation": 5,
      "missionFit": 3,
      "supportMaterials": 4,
      "strength": 2,
      "completionMaterials": null
    },
    "notes": {
      "correctionAccuracy": "근거 한 줄",
      "missionFit": "근거 한 줄"
    }
  }
]
```

- 점수는 1~5의 정수다. 해당 없으면 `null`로 둔다.
- `notes`에는 점수마다 근거를 한 줄씩 쓴다. 학생 답이나 피드백의 문구를 짧게 인용한다.

## 항목

각 항목의 1·3·5점 기준이다. 2점과 4점은 그 사이로 매긴다.

### ① 교정 정확성 `correctionAccuracy`

학생 답의 문법·구조 오류를 맞게 고쳤는지, 틀리지 않은 것을 고치지 않았는지 본다.

- 해당 없음: 교정 줄이 없고, 학생 답에 고쳐야 할 오류도 없을 때. 오류가 있는데 교정이 없으면 해당 없음이 아니라 낮은 점수다. 미션이 문장 교정이 아니면 교정 줄이 화면에 없으므로, 학생 답의 오류를 피드백이 무시한 것이 적절한지(더 급한 내용 미션이 있었는지)는 ③에서 본다. 이때 ①은 해당 없음이다.
- 5: 교정마다 실제 오류이고, 고친 결과가 표준 영어로 맞고, 학생의 뜻을 바꾸지 않았다. 고칠 만한 오류를 빠뜨리지 않았다.
- 3: 대체로 맞지만 하나쯤 틀렸다. 예를 들어 자연스러움일 뿐인 것을 문법 오류처럼 고쳤거나, 오류 하나를 놓쳤거나, 고친 결과에 어색함이 남았다.
- 1: 맞는 문장을 틀렸다고 고치거나, 고친 결과가 틀렸거나, 학생의 뜻을 바꿨다.

### ② 교정 설명 `correctionExplanation`

교정 줄의 한국어 이유가 정확하고, 학생 수준에서 이해하기 쉬운지 본다.

- 해당 없음: 교정 줄이 없을 때.
- 5: 이유마다 그 교정을 정확히 설명한다. 짧고 쉬운 한국어이고, 다음에 같은 실수를 피할 단서(규칙이나 구별법)를 준다.
- 3: 맞지만 막연하다("문법에 맞게 고쳤어요"), 길거나 용어가 어렵다, 또는 한 줄이 다른 교정을 섞어 설명한다.
- 1: 이유가 틀렸거나, 교정과 맞지 않거나, 비어 있다.

### ③ 미션 적절성 `missionFit`

이 답에서 지금 가장 필요한 한 가지를 미션으로 짚었는지 본다. 완료면 "더 고칠 것 없이 완료로 본 것"이 맞는지 본다.

- 5: 학생이 다음에 고치면 답이 가장 나아지는 한 가지다. 제목과 이유(`why`)가 그 점을 구체적으로 말한다. 완료라면 정말 질문에 충분히 답했다.
- 3: 고칠 만한 점이지만 더 급한 것이 있다. 예를 들어 질문의 핵심 내용이 빠졌는데 가벼운 문법을 짚었다. 또는 이유가 막연하다.
- 1: 엉뚱한 것을 짚었다. 예를 들어 이미 쓴 내용을 쓰라고 하거나, 문제가 아닌 것을 문제라고 했다. 또는 분명히 부족한 답을 완료로 끝냈다.

### ④ 도움 자료 `supportMaterials`

다시 쓸 때 돕는 자료(다시 쓸 때 안내, 문장 틀, 넣어볼 표현)가 질문 난이도에 맞고 바로 쓸 만한지 본다.

- 해당 없음: 완료일 때. 또는 문장 교정 미션이라 문장 틀·넣어볼 표현이 없을 때(안내 문구만 있으면 해당 없음).
- 5: 문장 틀이 미션에 딱 맞고 학생 답에 바로 이어 쓸 수 있다. 영·한 뜻이 맞다. 넣어볼 표현이 난이도에 맞고 서로 다른 선택지이며, 학생이 말하지 않은 사실을 지어내게 하지 않는다.
- 3: 쓸 수는 있지만 일반적이다. 또는 난이도보다 어렵거나 쉽다. 또는 표현 하나가 미션과 덜 맞는다.
- 1: 미션과 맞지 않거나, 틀린 영어가 있거나, 영·한 뜻이 다르거나, 학생 대신 답을 다 써 준다.

### ⑤ 잘한 점 `strength`

잘한 점이 이 답에 대해 구체적이고 사실인지 본다.

- 해당 없음: 잘한 점이 비어 있고, 학생 답에서 칭찬할 만한 점을 찾기 어려울 때(주제에서 벗어난 답 등).
- 5: 학생 답의 특정 부분을 짚어 무엇이 좋은지 말하고, 사실이다.
- 3: 사실이지만 어느 답에나 쓸 수 있는 말이다("질문에 맞게 답했어요").
- 1: 사실이 아니다. 예를 들어 없는 내용을 칭찬하거나, 틀린 부분을 잘했다고 했다.

### ⑥ 완료 화면 자료 `completionMaterials`

완료일 때 보이는 모범 답안·해석·추천 표현·풍부하게 써 보기 제안이 학생 답을 살리는지 본다.

- 해당 없음: 완료가 아닐 때.
- 5: 모범 답안이 질문 난이도에 맞고 학생의 뜻과 사실을 살린다. 해석이 정확하다. 추천 표현이 서로 다른 쓰임이고, 학생 답에 바로 넣을 수 있으며, 예문이 맞다.
- 3: 맞지만 학생 답과 따로 논다(새 사실을 많이 지어냄). 또는 표현이 평범하거나 난이도에 어긋난다.
- 1: 틀린 영어가 있거나, 해석이 다르거나, 학생 답과 관계없다.

## 채점자에게

- 피드백이 "그럴듯한가"가 아니라 "이 학생의 이 답에 맞는가"를 본다. 학생 답을 먼저 읽고 피드백을 읽는다.
- 케이스의 "볼 점"(`expectedBehavior`)은 평가셋을 만든 사람이 기대한 것이다. 참고하되, 피드백이 다른 방식으로 더 좋으면 그 점을 인정한다. 볼 점에 적힌 고친 꼴은 예시이므로, 같은 뜻의 다른 맞는 고침도 감점하지 않는다. 볼 점이 "고치면 과잉 교정"이라고 적은 표현을 고쳤으면 ①에서 감점한다.
- 영어가 맞는지 확신하지 못하면 그 점을 근거에 적고, 확실히 틀린 것만 감점한다.
